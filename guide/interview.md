# 模拟面试：把结论卡和两个项目讲出来

> 课程和两个项目做完，你手上有结论卡、PRD、方案、代码、也许还有上线地址。这一页教你怎么在面试里讲它们，以及三个一定会被追问的问题。两人一组练，一人当面试官。

---

## 面试官的第一句话

多半是这句：**「讲一个你做过的 Agent 产品。」**

不要从技术讲起。按下面六步讲，每一步对应一份你手上的文件：

| 步骤 | 讲什么 | 翻哪份文件 |
|---|---|---|
| 场景 | 给谁用、他原来怎么做、哪里难受 | 结论卡第 1 项；PRD 第 1、2 节 |
| 症状 | 如果用普通程序或一次模型调用，会出什么问题 | 结论卡第 1 项「需要 Agent 的环节」 |
| 组件 | 为了治这些症状，启用了哪几个组件；哪些故意没用 | 结论卡第 3 项；`方案.md` 组件选型 |
| 代价 | 每个组件带来的成本：钱、慢、复杂、风险 | 各章「产品经理视角」 |
| 规则 | 权限三档、步数费用上限、什么时候交给人 | 结论卡第 4 项；`方案.md` 工具清单的权限列 |
| 指标 | 怎么知道它做得好不好，目标值是多少 | 结论卡第 5 项；工具包的证据包 |

讲完六步再说路线：**「真实世界我会选哪条路，课堂上为什么走了自研。」** 两行都讲，比只说「我自研了一个」强得多。

## 三个一定会被追问的问题

### 追问一：「为什么不直接用 Coze、Dify 这类平台？」

**面试官想听的**：你知道五条路，知道自研不是默认选项，知道这件事该怎么判断。

**答得好的样子**：先承认大多数产品不该自研。再按五个问题过一遍自己的产品：内部用还是给客户用、有没有工程师、模型和数据有没有限制、Harness 是不是核心竞争力。给出真实路线，再说课堂路线是自研，目的是把每个组件亲手造一遍，看懂平台帮你做了什么、没做什么。最后补一句：平台缺哪个组件对你的产品致命，你是怎么对照出来的。

**常见扣分**：说「自研更灵活」却举不出平台缺什么；不知道平台自带哪些组件；把自研当成能力的证明而不是判断的结果。

### 追问二：「这个组件去掉会怎样？」

面试官会随手指你方案里的一个组件，常指权限、钩子、记忆。

**面试官想听的**：组件不是凭感觉加的，每个都对应一个症状，去掉就会出那个症状。

**答得好的样子**：说出去掉以后用户会看到的具体现象。比如去掉权限，Agent 会在没人确认的情况下删客人的记录；去掉记忆，客人下次来还要重新问口味。再说这个组件的代价是什么，所以你把它放在哪一档：第一版就上，还是出现症状再加。如果能说出「我原来结论卡里没选它，工坊引擎建议选，我最后为什么听或不听」，是满分答案。

**常见扣分**：答「这是 Agent 的标配」；说不出去掉后的具体现象；所有组件都说重要。

### 追问三：「上线以后出过什么问题，你怎么改的规则？」

**面试官想听的**：你盯过指标，改过规则，知道产品经理在 Agent 产品里管的是规则和边界，不是代码。

**答得好的样子**：举一个具体的事。哪条指标不对，或者哪次 Agent 做了不该做的事。然后说你改了哪条规则：某个操作从「放行」改到「先问人」，步数上限从多少降到多少，某类数据不再记。再说改完指标怎么变的。证据在工具包每个阶段的证据包和 `迭代记录.md` 里，面试前翻一遍。

没上线的同学也能答：说本地跑通时 `verify` 报告里哪一条让你改了规则，或者工坊的审稿意见里哪一条你接受了、哪一条你没接受。

**常见扣分**：说「没出过问题」；只讲修了什么代码；没有数字。

## 自评表

两人一组，面试官照着这张表打勾，讲完互换。

| # | 做到了吗 |
|---|---|
| 1 | 开头先讲场景和症状，不是先讲技术 |
| 2 | 六步都讲到，每一步能说出翻哪份文件 |
| 3 | 真实路线和课堂路线都讲了，并说清为什么不一样 |
| 4 | 被问「去掉会怎样」时，说出了用户能看到的具体现象 |
| 5 | 至少讲了一条自己改过的规则，带前后对比 |
| 6 | 至少有一个数字：指标目标值、步数上限、费用上限都算 |
| 7 | 有一处和机器意见不一致并讲清了理由 |

5 项以上打勾，可以去面试了。

## 练之前准备什么

把下面几份文件打开放在手边，面试官追问时你翻得出来：

- 结论卡（课程练习第 7 题）
- `out/<产品名>/PRD.md`，特别是第 6 节「我为什么不听机器的」
- `out/<产品名>/方案.md` 的组件选型和工具清单
- 工具包的《技术适配声明》和各阶段证据包
- 上线地址，如果有
