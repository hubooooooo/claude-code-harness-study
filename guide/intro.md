# 第 0 课 · 导读：这门课要你学会什么

> 开始 s01 之前，先花 10 分钟读完这一篇：后面 17 章在学什么，为什么这样学，每章该看哪里。

---

## 一句话说清这门课

**用自研的方式学：照着 Claude Code，把一个 Agent 的部件亲手造一遍。学会的是判断：拿到一个产品需求，能说清楚该走哪条路、用哪些部件、规则怎么定。**

**不要求你会写代码。** 每章附带能运行的基础代码，真要改，交给 AI 改。你只需要看懂原理、做出判断。

### 学完要达到的标准

给你一个产品需求，你能准确判断：

1. **要不要用 Agent**。有些需求根本不需要。
2. **五条路走哪条**：直接用成品、用厂商开发包、用通用框架、用低代码平台，还是完全自研。
3. **部件怎么定**：自研，就从 16 个部件里挑；不自研，就对照这条路缺哪些部件、致不致命。

判断流程和「判断结论卡」在 [选型篇](README.md) 开头，结课用 [练习](practice.md) 里的综合验收题检验。

## 开始前先认识五个词

| 词 | 意思 |
|---|---|
| **大模型** | 负责思考的 AI，比如 Claude、GPT、DeepSeek。给它一段文字，它写出一段回答 |
| **API Key** | 程序调用大模型要用的「钥匙」，相当于账号密码。调用按用量收费 |
| **token** | 模型计算文字长短的单位，可以粗略理解成「字数」。费用和长度上限都按它算 |
| **上下文** | 模型每次回答时能看到的全部内容：你说过的话、它的回答、工具返回的结果。长度有上限 |
| **工具调用** | 模型自己没法动手，只能说「请帮我执行这个命令」，由程序去执行，再把结果告诉它 |

更多的词见 [名词表](glossary.md)，随时回来查。

## Agent 和聊天机器人差在哪

| | 你说「看看这个文件夹里有哪些文件，再把里面的 Python 程序跑一下」 |
|---|---|
| **聊天机器人** | 告诉你该输入什么命令。你得自己去跑，再把结果贴回给它，它才能接着说 |
| **Agent** | 自己跑命令、看结果、决定下一步，直到做完 |

把「你来回贴结果」这件事自动化，就是 s01 要造的东西。

## 三层：模型、Harness、产品

| 层 | 是什么 | 比喻 | 以 Claude Code 为例 |
|---|---|---|---|
| **模型** | 负责思考和做决定 | 司机 | Claude |
| **Harness** | 让模型能动手干活的一整套机制 | 车 | 反复调用模型的循环、读写文件的工具、危险操作前的确认、长对话压缩、记忆…… |
| **产品** | 用户看到和用到的东西 | 车的外观、售价、售后 | 终端界面、各种命令、订阅收费 |

模型由几家大厂训练，大多数公司只能挑选；产品界面谁都会关注。夹在中间的 Harness 决定了 Agent 能做什么、不能做什么、出错了怎么兜底。**它最容易被忽视，也最能体现产品经理的判断力。这门课只讲这一层。**

## 为什么用自研的方式学

做一个 Agent 产品，有五条路：

| 路线 | 比喻 | 代表 |
|---|---|---|
| 直接用成品 | 买一辆整车 | Claude Code、Codex |
| 用厂商开发包 | 买底盘，自己装车身 | Claude Agent SDK、OpenAI Agents SDK |
| 用通用框架 | 买标准零件自己组装 | LangChain、LangGraph |
| 用低代码平台 | 用乐高拼 | Dify、Coze |
| **完全自研** | 自己造车 | **这门课的做法** |

现成方案把部件都藏在里面，你只看得到外面的按钮。自己造一遍，才知道每个部件解决什么问题、要付出什么代价、哪些规则该由产品经理来定。学完以后，拿到任何框架都能在几分钟内看出它带了什么、缺了什么。

**但这不等于你的产品就该自研。** 真做产品时，按顺序问五个问题：

1. 这件事真的需要 Agent 吗？
2. 是给自己团队提效，还是做进产品给客户用？
3. 团队里有没有工程师？
4. 要不要换模型？有没有数据或合规限制？
5. Harness 本身是不是你的核心竞争力？

怎么落到一条路上，在 [选型篇](README.md) 里展开讲。

## 每一章怎么读

每章顺序相同：**本章要学会的判断 → 问题 → 解决方案 → 工作原理 → 试一下 → 产品经理视角 → 接下来**。没有编程基础，这样读：

1. **开头的「本章要学会的判断」先读**，带着它往下看。
2. **「问题」一定要读**：没有这个部件会出什么麻烦，这就是「信号」。
3. **「解决方案」看图就够。**
4. **「工作原理」里的代码可以跳过**，到「回放」里一步步看机制怎么转。
5. **「产品经理视角」重点读**：信号、代价、替代办法、你要拍板的规则、怎么衡量，最后一道面试题。
6. 有余力，在「运行」里亲手跑一次（需要 API Key）。

---

## 每学完一章，问自己三个问题

- 不加这个部件，会出什么问题？
- 加上它，要付出什么？
- 如果我是产品经理，哪条规则要我来定？

三个都能用自己的话答出来，这一章就算学会了。
