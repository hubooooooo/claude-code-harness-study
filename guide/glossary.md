# 名词表

> 课程里遇到看不懂的词，回这里查。不用一次读完，用到时查一下就行。每个词后面标了它主要出现在哪一章。

---

## 一、基本概念

| 词 | 意思 | 出现在 |
|---|---|---|
| **大模型 / 模型** | 负责思考的 AI，比如 Claude、GPT、DeepSeek。给它一段文字，它写出一段回答 | 全程 |
| **Agent** | 能自己决定下一步、动手做、看结果、再决定下一步的 AI 系统。和一问一答的聊天机器人不同 | 导读、s01 |
| **Harness** | 让模型能动手干活的一整套机制：循环、工具、权限、记忆等。模型是司机，Harness 是车 | 导读 |
| **组件** | 本课程对 Harness 里单个机制的叫法。s01～s14、s16、s17 每章一个，共 16 个 | 导读 |
| **组件数怎么数** | 本课说 16 个组件加 1 章总装，s15 不算组件。《Agent 工坊》把 s15 也算进去，所以那边数到 17。两边指的是同一套 s01～s17 | 导读、学习路线总导读 |
| **总装** | s15 的做法：不加新组件，把前面的组件装进同一个循环 | s15 |
| **提示词（prompt）** | 发给模型的文字指令 | 全程 |
| **系统提示词（system prompt）** | 每次调用模型时都放在最前面的固定说明，比如「你是一个客服，只回答售后问题」 | s07、s09、s13 |
| **幻觉** | 模型一本正经地编造不存在的内容。这是 s03 权限、s17 目标判断这类兜底机制存在的原因之一 | 常见说法 |

## 二、调用模型

| 词 | 意思 | 出现在 |
|---|---|---|
| **API** | 程序调用模型的接口。程序把文字发过去，模型把回答发回来 | s01 |
| **API Key** | 调用 API 要用的「钥匙」，相当于账号密码。调用按用量收费，不能泄露 | 安装、s01 |
| **token** | 模型计算文字长短的单位，可以粗略理解成「字数」。费用和长度上限都按它算 | s08 |
| **上下文 / 上下文窗口** | 模型每次回答时能看到的全部内容：你说过的话、它的回答、工具结果。有长度上限，超过就会报错 | s06、s08 |
| **SDK / 开发包** | 厂商提供的一套现成代码，让工程师少写很多基础代码。比如 Claude Agent SDK | 选型篇 |
| **框架** | 和具体厂商无关的通用开发工具，比如 LangChain、LangGraph。可以换不同的模型 | 选型篇 |
| **低代码平台** | 在网页上拖拽、配置就能搭 Agent 的工具，比如 Dify、Coze。不太需要写代码 | 选型篇 |

## 三、循环里的东西

| 词 | 意思 | 出现在 |
|---|---|---|
| **循环（Agent Loop）** | 反复调用模型：模型要用工具就执行、把结果交回去；模型不再用工具就结束 | s01 |
| **messages** | 程序里保存对话记录的列表。每次调用模型，都把整个列表发过去 | s01 |
| **工具（tool）** | Agent 能做的一个动作，比如读文件、执行命令、查订单 | s02 |
| **tool_use / 工具调用** | 模型回答里的一段内容，意思是「请帮我用某个工具，参数是……」 | s01、s02 |
| **tool_result / 工具结果** | 程序执行完工具后交回给模型的结果 | s01、s02 |
| **handler** | 真正执行某个工具的那段代码。模型只负责说「要用哪个工具」，handler 负责去做 | s02 |
| **Bash / Shell / 终端** | 在电脑上输入命令执行操作的方式。s01 里 Agent 唯一的工具就是它 | s01 |
| **命令** | 在终端里输入的一行指令，比如「列出文件」「删除某个文件夹」。模型写出来，程序替它执行 | s01、s03 |
| **子命令 / 管道** | 一行里用分号、竖线把几条命令连起来。权限规则按每一小段真正要执行的程序名来判断 | s03 |
| **查表分发（dispatch）** | 模型只说工具名，程序拿名字去一张表里找真正干活的代码。加工具只要在表里加一行 | s02 |
| **项目文件夹 / 工作区** | Agent 被允许读写的那个文件夹。读写文件的工具出了这个范围会被拦下；执行命令的工具不受这个限制 | s02、s03 |
| **黑名单** | 永远不许做的事的清单，命中就直接拒绝，连问都不问 | s03 |
| **危险命令** | 做了就收不回来的操作：删文件、改系统设置、取得管理员权限。本课的规则是遇到就停下来问人 | s03 |
| **管理员权限（sudo）** | 在电脑上做任何事都不受限制的身份。要拿到它的命令一律进黑名单 | s03 |
| **删光整台电脑（rm -rf /）** | 一条把电脑上所有文件全部删掉的命令。课程里用它当「绝对禁止」的例子 | s02、s03 |
| **提示词注入** | 网页、邮件、文档里藏着的指令，诱导模型做本不该做的事 | s03、案例 |

## 四、各个组件的叫法

> 《Agent 工坊》里的叫法略有不同，比如这里的「待办」在工坊里叫「任务规划」、「任务板」叫「任务系统」。完整对照表见 [学习路线总导读](../学习路线总导读.md)。

| 词 | 意思 | 出现在 |
|---|---|---|
| **权限（permission）** | 判断一个操作能不能做、要不要先问人 | s03 |
| **钩子（hook）** | 在固定时机（比如工具执行前、执行后）自动运行的检查或记录 | s04 |
| **待办（Todo）** | Agent 自己列的计划清单，做完一项勾一项 | s05 |
| **子 Agent（subagent）** | 被主 Agent 派去做子任务的另一个 Agent，只把结论交回来 | s06 |
| **技能（skill）** | 一份专门的操作规范。平时只露出目录，用到时再展开全文 | s07 |
| **压缩（compact）** | 上下文快满时，把旧内容精简或总结，腾出空间 | s08 |
| **记忆（memory）** | 跨对话保存下来的信息，比如用户偏好 | s09 |
| **任务板（task）** | 保存在文件里的任务清单，带先后关系，可以跨会话继续 | s10 |
| **后台任务** | 放到后台慢慢跑的操作，跑完再通知 Agent | s11 |
| **定时（cron）** | 到了设定的时间自动触发任务 | s12 |
| **团队（team）** | 多个 Agent 分工协作、互相发消息 | s13 |
| **worktree** | 给每个任务单独复制一份工作目录，几个 Agent 同时改代码时互不干扰 | s13 |
| **MCP** | 一种通用的接口标准，用它可以把外部系统和工具接进 Agent | s14 |
| **工作流（workflow）** | 事先写好的固定流程脚本，按步骤调用模型 | s16 |
| **journal** | 工作流每做完一步就记一笔的运行记录。中断后重跑，做过的步骤直接用记录里的结果 | s16 |
| **目标判断（goal）** | 模型说做完了以后，由独立的裁判检查是否真的达到目标 | s17 |
| **催更** | 连续几圈没更新待办清单，程序往工具结果里塞一句提醒 | s05 |
| **派活** | 把一件独立的小任务交给子 Agent，它干完只汇报结论 | s06 |
| **摘要** | 记录本太长时，让模型把旧历史总结成几句事实，换掉原文；原文存档在硬盘 | s08 |
| **召回 / 提取** | 召回：问模型前挑出相关的几条记忆放进提示词。提取：聊完后由模型判断哪些话值得长期记住 | s09 |
| **前置 / 认领** | 前置：这个任务要等哪些任务先完成。认领：一个 Agent 把待处理的任务标成自己在做 | s10、s13 |
| **线程** | 程序里能同时干活的一条「小工」。后台任务、定时器都靠它在旁边跑 | s11、s12 |
| **完成通知** | 后台任务跑完后，下一圈问模型之前塞进记录本的那一句话 | s11 |
| **调度线程** | 每秒看一眼定时任务表，到点就把任务放进待送队列的小工 | s12 |
| **主控 / 队友 / 信箱** | 主控：和你对话、派人、审批的 Agent。队友：有自己记录本和工具的 Agent。信箱：每人一个文件，谁都能给谁留言 | s13 |
| **工具池** | 自带工具和外部工具放在一起的那张清单，每圈重新拼 | s14、s15 |
| **错误恢复** | 调用模型出错时重试、换备用模型、回答被截断就接着写。s15 唯一新增的代码 | s15 |
| **续跑** | 工作流中途断了，从断点接着跑；做过的步骤直接用调用日志里的结果，不再花钱 | s16 |
| **判断器 / 打回** | 判断器：另一次不带工具的模型调用，只看证据说完没完。打回：判断器说没完，把理由塞回记录本再转一圈 | s17 |

## 五、做产品时常见的词

| 词 | 意思 | 出现在 |
|---|---|---|
| **沙箱** | 一个隔离的运行环境。Agent 在里面出了错，也影响不到外面的真实系统 | s03、选型篇 |
| **白名单** | 只允许清单里的东西通过，其余一律不行。比如只允许接入名单上的外部服务 | s14、案例 |
| **审计 / 留痕** | 把谁在什么时候做了什么记录下来，出了问题能追查 | s04、案例 |
| **脱敏** | 把手机号、身份证号这类敏感信息遮掉或替换掉 | s04、s14、案例 |
| **软删除** | 先放进回收站而不是真删，删错了还能恢复 | 选型篇 |
| **人工介入 / 转人工** | Agent 处理不了或不该处理时，把事情交给人 | 选型篇、案例 |
| **检索** | 先从文档库里找出相关段落，再交给模型回答。常说的 RAG 就是这种做法 | 案例 |
| **私有部署** | 把模型或系统装在公司自己的服务器上，数据不出公司 | 选型篇 |
| **多租户** | 一套系统同时服务多家客户，各家数据互相隔离 | 选型篇 |
| **许可证** | 开源软件的使用条款，规定能不能商用、能不能改、能不能拿去卖服务 | 选型篇 |
| **工单 / CRM** | 企业里常见的系统：工单系统记录客户问题，CRM 管理客户信息 | s14、案例 |
| **RPA** | 模仿人点鼠标、填表格的自动化工具，适合步骤完全固定的重复操作 | s16、选型篇 |
