# 案例：竞品和舆情日报

这个案例的结论是：**大部分环节不需要 Agent。**

面试里，能说出「这个场景我不建议用 Agent」并讲清理由，往往比把 17 个部件全用上更能体现判断力。

---

## 1. 背景

一个消费品牌的市场部，每天早上需要一份「竞品和舆情日报」：

- 几个主要竞品有没有上新品、改价格、做活动；
- 社交媒体上关于自家品牌的讨论，尤其是负面的。

现在由一名实习生每天花 2 小时手工整理，9 点半发到飞书群。老板说：「做个 Agent，每天自动出。」

已知条件：

| 条件 | 情况 |
|---|---|
| 团队 | 市场部没有工程师；IT 部门排期要等两个月 |
| 数据 | 竞品官网、电商店铺、几个社交平台；都是公开信息 |
| 入口 | 结果发到飞书群 |
| 格式 | 每天一样：竞品动态、自家舆情、需要关注的事 |

---

## 2. 先问：真的需要 Agent 吗？

把实习生每天做的事拆开：

| 步骤 | 每天都一样吗 | 需要「看结果决定下一步」吗 |
|---|---|---|
| ① 打开固定的十几个来源，收集新内容 | 一样 | 不需要 |
| ② 去掉重复的、无关的 | 一样 | 不需要 |
| ③ 每条写一句摘要，判断正面还是负面，归类 | 一样 | 不需要，但需要「理解内容」 |
| ④ 按固定格式汇总 | 一样 | 不需要 |
| ⑤ 9 点半发到飞书群 | 一样 | 不需要 |

**结论**：五个步骤全部固定，没有一步要根据上一步的结果决定接下来做什么。真正需要 AI 的只有第 ③ 步，而且每条内容**调用一次模型**就能完成。

所以这个需求要的不是 Agent，而是：**定时触发 + 固定流程 + 在其中一步调用模型。**

> 产品经理的判断点：老板说「做个 Agent」，不等于真的需要 Agent。先把流程拆开，逐步问：这一步每天一样吗？需要看情况决定下一步吗？两个答案都是「一样、不需要」，就不该上 Agent 循环。

用 Agent 会怎样？每天走的步数不确定，费用不稳定；偶尔会漏掉某个来源，或者多搜了一堆无关内容；格式时好时坏。这些问题，固定流程都没有。

---

## 3. 走哪条路？

| 问题 | 这个案例的回答 | 指向 |
|---|---|---|
| ① 真的需要 Agent 吗 | 主流程不需要 | 用工作流 |
| ② 内部提效还是做进产品 | 内部提效 | — |
| ③ 有没有工程师 | 没有，IT 要排期两个月 | **用低代码平台** |

后面两个问题不用再问了。

**结论：用低代码平台的工作流功能，加上定时触发。** Dify 这类平台，或者 n8n 这类自动化平台都可以，市场部的运营同事学一两天就能搭起来。

选型篇的对照表里，Dify 的「定时」和「工作流」两项都是自带的，正好是这个需求最需要的两个部件。反过来，它偏弱的权限和钩子，在一个只读公开信息、只往内部群发消息的场景里，影响很小。

---

## 4. 逐个部件：用、暂不用、不用

| 部件 | 决定 | 理由 |
|---|---|---|
| s01 循环 | **不用** | 流程固定，不需要模型决定下一步 |
| s02 工具 | 用，但是固定节点 | 抓取网页、调用数据接口、发飞书消息，在流程里按顺序执行，不让模型挑 |
| s03 权限 | 基本不用 | 只读公开信息，只往内部群发消息；唯一的限制是只能发到指定的群 |
| s04 钩子 | 用平台自带的运行记录代替 | 每天跑没跑、哪一步失败，平台的运行记录里都能看到 |
| s05～s11 | 不用 | — |
| s12 定时 | **用，平台自带** | 每个工作日 9 点触发 |
| s13、s14 | 不用 | — |
| s16 工作流 | **用，这个案例的核心** | 五个步骤固定编排 |
| s17 目标判断 | 用程序检查代替 | 发出前检查：每条内容都附了来源链接，三个栏目都不为空，否则通知负责人 |

**数一下**：真正用到的只有定时和工作流两个部件，加上流程中的几次模型调用。这是整个课程里最「省」的方案，也是这个需求最合适的方案。

---

## 5. 规则清单

| 类别 | 规则 |
|---|---|
| 来源 | 只抓白名单里的来源；遵守各平台的使用规则，优先用官方接口或正规的数据服务商 |
| 内容 | 每条必须附原文链接；摘要不加入原文没有的信息 |
| 判断 | 模型对情感判断不确定时，标为「待人工确认」，不硬判 |
| 预警 | 负面讨论数量比前一天多一倍以上时，不等日报，立刻单独提醒品牌负责人 |
| 边界 | 日报只做汇总，**绝不自动对外回应**任何评论 |
| 推送 | 只发到指定的飞书群；节假日不推送 |

---

## 6. 指标

| 指标 | 怎么算 | 目标 |
|---|---|---|
| 准时率 | 9 点半之前送达的天数比例 | ≥ 99% |
| 漏报率 | 每周人工抽查一天，对比手工整理的结果，看漏了多少 | ≤ 10% |
| 误判率 | 正负面判断错误的比例 | ≤ 10% |
| 打开和讨论 | 群里有没有人看、有没有人回复跟进 | 持续下降就要调整内容 |
| 节省时间 | 实习生每天节省的时间 | 从 2 小时降到 15 分钟（只做复核） |
| 月费用 | 平台费加模型费用 | 每月几百元以内 |

---

## 7. 迭代路线：Agent 在哪里才真正有用

| 版本 | 内容 | 用到的部件 |
|---|---|---|
| V1 | 固定流程的日报 | 定时、工作流 |
| V2 | 负面舆情突然增加时，自动启动一个**调研 Agent**：顺着讨论追查起因，整理成一份说明给品牌负责人 | 循环、工具（只读）、子 Agent 式的独立调研 |
| V3 | 每周五自动汇总成周报，标出趋势 | 定时、工作流 |

注意 V2：追查「为什么负面突然变多」时，要搜什么、搜到以后再往哪里追，每次都不一样，**这时候 Agent 才真正有用**。所以合理的设计是：主流程用固定工作流，只在异常时启动一个只读的 Agent。

---

## 8. 面试时怎么讲（一分钟版）

> 老板让我做一个每天自动出竞品和舆情日报的 Agent。我先把流程拆成五步，发现每一步都是固定的，没有一步需要根据结果决定下一步，真正需要 AI 的只是给每条内容写摘要、判断正负面，调用一次模型就够了。
>
> 所以我没有用 Agent，而是用低代码平台搭了一个定时触发的固定工作流。市场部自己就能维护，不用等 IT 排期，费用每月几百元。
>
> Agent 用在一个更合适的地方：负面讨论突然增加时，自动启动一个只读的调研 Agent 去追查原因，因为这件事每次的查法都不一样。
>
> 衡量看准时率、漏报率和误判率，实习生每天的整理时间从 2 小时降到 15 分钟。
